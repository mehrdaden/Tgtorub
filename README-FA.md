# tg2rub v6.1 — ربات تلگرام ← روبیکا

فایل یا **لینک** را به ربات تلگرام بفرست؛ با دکمه‌ها نام، ZIP (رمز AES-256 اختیاری)، تقسیم به N قسمت را تنظیم کن و به
Saved Messages روبیکا آپلود کن. درصد دریافت دقیق (یا تخمینی در صورت نبود حجم کل) و درصد آپلود تخمینی با نوار گرافیکی نمایش داده می‌شود؛ بعد از آپلود موفق، فایل طبق تنظیم حذف خودکار پاک می‌شود.

## لینک‌ها
- **فایل مستقیم** (زیپ، ویدئو، pdf، لینک سایت‌های ایرانی و ...): دانلودر داخلی با چند اتصال هم‌زمان و ادامه‌ی خودکار.
- **صفحه‌ی ویدئو** (یوتیوب، اینستاگرام، X/توییتر، تیک‌تاک و صدها سایت): با yt-dlp. تک‌ویدئو؛ پلی‌لیست دانلود نمی‌شود. سایت‌های بزرگسال (+۱۸) نیز در صورت پشتیبانی extractor یا Generic توسط yt-dlp قابل‌دریافت‌اند.
- چند لینک در یک پیام (تا ۵) = چند دانلود جدا.
- سایت‌هایی که ورود می‌خواهند: `COOKIES_FILE` ؛ سایت‌های محدود به منطقه: `LINK_PROXY` (در `.env`). فایل کوکی فعلی سراسری است و به‌صورت حساب جداگانه برای هر کاربر مدیریت نمی‌شود؛ آن را در چت یا GitHub ارسال نکن.
- سایت‌ها زود‌به‌زود عوض می‌شوند: `/ytdlp_update` دانلودر را به‌روز می‌کند.
- یوتیوب به JavaScript runtime سازگار نیاز دارد؛ نصب‌کننده Deno نسخه ۲.۳ یا بالاتر را بررسی و در صورت نیاز نصب می‌کند. در خطای 403/SABR/PO Token، دانلودر یک بار با کلاینت `web_safari` هم تلاش می‌کند.

## ورود حساب X / Twitter
در این نسخه قابلیت اتصال حساب X اضافه نشده است. OAuth رسمی X توکن API می‌دهد، اما `yt-dlp` برای سایت‌هایی که نیاز به ورود دارند از کوکی مرورگر در قالب Netscape استفاده می‌کند؛ این دو جایگزین هم نیستند. اضافه‌کردن ورود ظاهری بدون اتصال واقعی به extractor فقط سطح نگهداری و ریسک نگهداری توکن را بالا می‌برد. راه فعلی، در صورت داشتن مجوز، استفاده از کوکی معتبر متعلق به خودت از طریق `COOKIES_FILE` است؛ این فایل محرمانه است.

## آپلود
- تا **۱۰ بار تلاش خودکار** با تغییر روش: نام اصلی ← نام ASCII ← پسوند `.bin` ← داخل ZIP.
- **نگهبان کندی:** اگر سرعت تخمینی آپلود (از شمارنده ترافیک خروجی سرور) ۹۰ ثانیه زیر `MIN_UPLOAD_KBPS` (پیش‌فرض ۶۰ کیلوبایت بر ثانیه) بماند،
  همان تلاش لغو و روی اتصال تازه تکرار می‌شود. این کار برای هر قسمت حداکثر ۳ بار انجام می‌شود؛ بعد از آن آپلود کند ولی در حال حرکت تمام می‌شود.
- **`/speed`** نشان می‌دهد گلوگاه کجاست (سرور، مسیر تا روبیکا، یا محدودیت هر اتصال). `/speed full` اتصال موازی را هم می‌سنجد.
  اگر نتیجه گفت اتصال موازی کمک می‌کند: `UPLOAD_STREAMS=3` بگذار و فایل را به چند قسمت تقسیم کن (قسمت‌ها هم‌زمان آپلود می‌شوند).
- اگر سرعت ناپایدار است `RUBIKA_MAX_MB=500` بگذار تا هر قسمت کوچک‌تر و تکرار ارزان‌تر باشد.

## نصب (Ubuntu 22.04 / 24.04)
    sudo apt update && sudo apt install -y unzip
    unzip -o tg2rub-v6.1.zip && cd tg2rub
    sudo bash install.sh
نصب مجدد روی نسخه‌ی قبلی تنظیمات و ورود روبیکا را حفظ می‌کند.

## تنظیمات
`/opt/tg2rub/app/.env` (بعد از تغییر: `sudo systemctl restart tg2rub`). همه‌ی گزینه‌ها: `env.example`

## عیب‌یابی
- لاگ: `journalctl -u tg2rub -f` ؛ در ربات: `/diag`
- اتصال تلگرام: `sudo systemctl stop tg2rub` سپس `sudo -u tg2rub /opt/tg2rub/app/venv/bin/python /opt/tg2rub/app/diag.py`
- **به‌روزرسانی:** فایل ZIP را در پوشه‌ای تازه استخراج کن و `sudo bash install.sh` را اجرا کن. تنظیمات و نشست روبیکا حفظ می‌شوند؛ فایل‌های برنامه قبل از جایگزینی در `/opt/tg2rub/backups/` پشتیبان گرفته می‌شوند.
- **یوتیوب:** yt-dlp به JavaScript runtime سازگار (Deno >=2.3 یا Node >=22) و بسته EJS هم‌نسخه نیاز دارد؛ این موارد در نصب بررسی می‌شوند. در برخی ویدئوها یوتیوب به PO Token نیاز دارد یا پاسخ 403/SABR می‌دهد؛ نسخه ۶ پس از شکست روش پیش‌فرض فقط یک بار `web_safari` را امتحان می‌کند. این fallback تضمینی نیست؛ ممکن است محدودیت IP، کوکی یا PO Token Provider لازم باشد. از `/ytdlp_update` برای به‌روزرسانی استفاده کن.
- **سایت‌های +۱۸:** لینک سایت‌های بزرگسال فقط در صورتی دانلود می‌شود که yt-dlp آن سایت/قالب را پشتیبانی کند یا لینک مستقیم فایل باشد. محتوای خصوصی، پولی، DRMدار یا محدودشده بدون مجوز دور زده نمی‌شود. برای محتوایی که حساب خودت مجاز به دیدنش است، کوکی معتبر و متعلق به خودت را با `COOKIES_FILE` بده. فقط محتوای قانونی و مربوط به بزرگسالان بالای ۱۸ سال را دریافت کن.
- **درصدها:** درصد دانلود با callback خود دانلودر دقیق است. درصد آپلود روبیکا در این نسخه تخمینی است، چون API عمومی Rubpy در این مسیر callback قابل‌اتکای بایت آپلود ارائه نمی‌کند؛ علامت `≈` یعنی تخمینی.
- **سرعت آپلود:** اگر سرعت برای ۹۰ ثانیه زیر ۶۰ KB/s بماند (پس از ۴۵ ثانیه مهلت شروع)، تا ۳ بار تلاش مجدد می‌شود. بعد از آن، آپلود کند اما در حال پیشرفت رها می‌شود تا بی‌جهت از صفر شروع نشود. پایش سرعت در حالت `UPLOAD_STREAMS=1` معتبرتر است.
- **آپلود موازی:** `UPLOAD_STREAMS` را روی ۱ نگه دار تا تست واقعی `/speed full` و تأیید سازگاری با نسخه Rubpy نصب‌شده انجام شود. PlayDL یک نمونه پیاده‌سازی موازی است، اما پچ داخلی آن بدون تطبیق نسخه و تست روی حساب واقعی در این پروژه اعمال نشده است.
- حذف کامل: `sudo bash uninstall.sh`


### نسخه پایتون

نصب‌کننده Python 3.11 را در Ubuntu 22.04 و 24.04 نصب می‌کند و محیط مجازی را با همان نسخه می‌سازد. Python پیش‌فرض سیستم تغییر نمی‌کند.

### پراکسی، TLS/SNI و سرعت آپلود

`LINK_PROXY` فقط برای دانلود لینک‌ها و yt-dlp است؛ مسیر ارتباطی Rubpy برای آپلود از آن عبور نمی‌کند. مخزن‌های patterniha شامل Xray سفارشی با TCP/TLS fragmentation، SNI/DPI workarounds و کلاینت‌های V2Ray هستند؛ این‌ها ابزار افزایش ذاتی پهنای‌باند نیستند و ممکن است فقط در بعضی مسیرها محدودیت DPI را دور بزنند. TLS ClientHello نیز صرفاً پیام آغاز مذاکره TLS است؛ ابزار مستقل افزایش سرعت نیست.

برای عبور دادن آپلود Rubpy از تونل باید پراکسی محلی Xray و پشتیبانی واقعی لایه HTTP/TCP مورد استفاده Rubpy از proxy/transport مشخص و روی نسخه دقیق Rubpy تست شود. این پشتیبانی در کد فعلی تأیید نشده؛ بنابراین نسخه ۶ عمداً SNI injection یا Xray را داخل فرایند آپلود تزریق نمی‌کند تا نشست روبیکا و آپلودهای فعال خراب نشوند. برای سنجش گلوگاه از `/speed` و `/speed full` استفاده کن؛ افزایش `UPLOAD_STREAMS` هم فقط پس از تست واقعی توصیه می‌شود.
